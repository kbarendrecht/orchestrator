Tracker


      
      

        Tracker
        none
      

      
Where a "file a story" answer goes, and the only
        setting here that is read-only: set tracker in
        config.json as mcp_server, host and an
        optional token_env. With none, that option is never offered
        rather than offered and refused.


      
      
What the agents write replies and stories in. Blank
        leaves it to the repo's own convention.


      
      
      
      
Makes a ref like sc-54841 clickable in the
        terminals and the markdown viewer. {id} is the number. Blank
        leaves story refs as plain text; #123 always links to the PR or
        issue on the forge.

    


    
    

      
Git


      
      
The branch your work is measured against: the
        merge-base for every diff, and what a rebase lands on. Usually
        origin/HEAD.


      
      
Only for a ref that names no remote. Left blank it is
        the part of the ref before the slash, which is what you want unless you
        fetch from one remote and diff against another.


      
      
Run first in every worktree the daemon cuts, with cwd
        set to the new tree. The half about the tree as a checkout: basing
        it on a fresh upstream, configuring the push remote, whatever this repo does
        to a branch before anyone works on it.


      
      
      
Run second, same cwd, and run even when the init above
        failed — the two answer different questions. The half about what the tree
        needs beside the code: links back to the main checkout, generated
        config, anything not in git.


      
      
Told to an agent whose conversation has just moved
        into the main checkout. The daemon already says which branch moved and where
        the session is now; this is the half only you know — that the dev stack runs
        here, say.


      
      
The same, for a conversation that has landed in a
        worktree.


      
      
Days since a conversation was last worked in. Its
        worktree is then removed, but only once it is clean, pushed and nothing is
        running in it. The conversation stays in the rail and a resume rebuilds the
        tree, so this frees disk rather than losing work. 0 never removes
        anything.

    


    

      
Reviews


      
      
Default is every open PR somebody else wrote,
        oldest first, with the ones that asked for you on top. Custom is that
        same queue with the fields below applied — so they are shown either way, and
        changing one switches this to custom for you. Command runs your own,
        printing the same JSON.


      
      

        
        
        
Where a PR sits when somebody asked for you by
          name.


        
        
And where it sits when the ask went to a team you
          are in, which anybody in it may pick up.


        
        
By name or through a team you are in. With this on,
          the pane's asked word has nothing left to narrow and goes.


        
        
Comma separated. A PR needs one of these to appear
          at all, including one that asked for you.


        
        
Labels that lift a PR above the rest, over one that
          asked for you by name — but under anything set to first above.


        
        
Labels that sink a PR to the end of the list. Still
          shown: yours to look at, just not first. A lift wins over a sink, so this
          does not move a PR that asked for you — set that ask to no special
          place if you want the label to win.


        
        
Labels that drop a PR from the queue. The only way
          to hide one, so there is never a question of which list won.


        
        
        
        
Conflicts and failing checks, and not drafts —
          the box above owns those. Each kind sinks below the not reviewable
          fold already, because it is waiting on its author; these two drop it
          instead.

      


      
      
    


    
    

      
Agent


      
      
What + worktree and + main start. Right-click
        either for the other one. An agent that is not installed falls back to the
        one you used last.


      
      
Let the main checkout hold more than one live session at
        a time. Off, because one checkout is one working tree and one git index: two
        agents there share both, the changed-files pane merges their edits without
        saying who wrote what, and one agent's git add stages the other's
        work. A worktree is the answer that carries none of those costs. Worktrees are
        always one at a time, whatever this says.


      
      
An agent's git push to the branch this
        project is measured against is refused, with "open a PR instead". Turn it off
        for a project that commits straight to its main branch. A force push still
        needs a lease, and deleting a remote branch is still refused. Applies after a
        restart.
