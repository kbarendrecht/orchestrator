Where a "file a story" answer goes, and the only setting here that is read-only: set tracker in config.json as mcp_server, host and an optional token_env. With none, that option is never offered rather than offered and refused.

What the agents write replies and stories in. Blank leaves it to the repo's own convention.

Git

The branch your work is measured against: the merge-base for every diff, and what a rebase lands on. Usually origin/HEAD.

Only for a ref that names no remote. Left blank it is the part of the ref before the slash, which is what you want unless you fetch from one remote and diff against another.

Run instead of the built-in review queue, printing the same JSON. For a repo that already ranks its own reviews.

Run in every worktree the daemon cuts itself (PR, resumed, relocated), just after creation. The seam for setup that Claude's own WorktreeCreate hook would do — it only fires for interactive worktrees, so PR ones would otherwise miss it. cwd is the new worktree.

Days since a conversation was last worked in. Its worktree is then removed, but only once it is clean, pushed and nothing is running in it. The conversation stays in the rail and a resume rebuilds the tree, so this frees disk rather than losing work. 0 never removes anything.

Sessions

Let the main checkout hold more than one live session at a time. Off, because one checkout is one working tree and one git index: two agents there share both, the changed-files pane merges their edits without saying who wrote what, and one agent's git add stages the other's work. A worktree is the answer that carries none of those costs. Worktrees are always one at a time, whatever this says.
